最终会产出哪些文件，取决于你有几个模块。以单个模块为例：

产出物数量说明
着陆页整个站点 1 个第一眼看到的门面页，上面写着这个作品集是什么、有多少内容，以及一个进入按钮

举例

一个模块下有 3 个 PC 页面和 3 个手机页面，那么最终是： 站点 1 个着陆页 + 该模块 1 个门户页 + 6 个原型页 = 8 个网页文件。 门户页只有一个，它里面的目录会列出全部 6 个原型。

这一阶段需要完成两件事。

第一，按下面的结构整理文件夹。整个网站的结构是固定的，照着摆就不会出错：

我的作品集/                     ← 这个文件夹就是整个网站
├── index.html                 门面页
├── .nojekyll                  空文件，不是网页，别删
└── 会员体系/                   每个模块一个文件夹，名字自己起
    ├── 02_PRD/                该模块的文档
    │   └── 需求文档.md
    ├── 03_原型设计/
    │   ├── 门户.html          门户页
    │   ├── manifest.json      门户页的数据
    │   ├── PC端/
    │   │   └── 01-首页.html
    │   └── 小程序/
    │       └── 01-首页.html
    └── assets/
        └── marked.min.js      排版库
这张图不用自己动手搭

你实际只需要准备两样东西：原型文件和文档。 图中的门面页、门户页、数据文件、排版库，以及那个空文件，都由 AI 助手按规范生成，不用你手工创建。

有多个模块时，把 会员体系/ 这一层整体复制一份，改成另一个模块名即可，内部结构相同； 着陆页上的进入按钮做成两个，分别指向各自的门户页。 文件夹名和 02、03 的编号都可以改，只是沿用下来的叫法，改成「文档」「原型」也能正常运行。

如果某张图片没有被原型页面内联，而是单独存放，放进原型所在的文件夹即可，不必再另建目录。

第二，移除所有不适合公开的信息。包括公司名称、真实姓名、真实电话、 其他公司的品牌标识。这一项在第七步会再次说明，其重要性高于技术操作。

第三步：注册 GitHub

3.1 注册账号

  1. 打开 github.com/signup
  2. 填写邮箱，设置密码，设置用户名
  3. 前往邮箱点击验证链接
注意：用户名的选择

用户名会成为网址的一部分，形式为 用户名.github.io。 建议使用中性、专业的名称。这个网址会发送给他人，也可能出现在简历或邮件中。

3.2 建立网上文件夹

GitHub 中存放文件的单位称为仓库。仓库名称同样会出现在网址中。

  1. 打开 github.com/new
  2. 在 Repository name 一栏填写名称，例如 my-portfolio
  3. 可见性选择 Public（公开）。免费账号的网页发布功能只对公开仓库开放
  4. 勾选 Add a README file。此项必须勾选，否则后续上传会失败
  5. 点击 Create repository

3.3 获取访问密钥

本地的文件要上传到 GitHub，需要一枚密钥，官方名称是访问令牌。 没有它，程序无法代你完成上传。

  1. 打开 github.com/settings/personal-access-tokens/new
  2. Token name 一栏填写任意名称，例如 portfolio
  3. Expiration（有效期）选择 90 days。到期重新生成即可，不建议选择永不过期
  4. 找到 Repository access，选择 Only select repositories，然后在下拉列表中勾选刚创建的仓库
  5. 找到 Permissions，展开 Repository permissions，找到 Contents，将权限改为 Read and write（可读可写）
  6. 滚动到页面底部，点击 Generate token
  7. 页面会显示一串以 github_pat_ 开头的字符。立即复制并保存。该内容只显示一次，关闭页面后无法再次查看
重要：密钥的保管

这枚密钥等同于账号的权限。不要发送给任何人，不要写在聊天记录中，不要上传到任何网站。 如发生泄露，请立即回到同一页面撤销并重新生成。

第四步：把材料放上去

这一步有两种做法，选其中一种即可。两种做法得到的最终结果相同。

做法一：由 AI 助手完成（推荐）

“交给 AI 助手”是把文件夹里的文件提供给对话窗口，有三种做法，选一种：

做法操作适用
上传压缩包 把「配套文件（交给 AI 用）」文件夹压缩成一个 zip，拖进对话框，或点附件按钮选择它 所有网页版 AI 都能用，最通用
直接说路径 不压缩，直接把该文件夹的完整路径写在对话里，例如“请读取 D:\教程\配套文件（交给AI用）” AI 助手装在电脑上、能读本地文件时
整个目录一起给 把上级的「在线作品集搭建教程」整个文件夹一起提供 希望它连说明一起读时

提供之后，再发送下面这段（方括号内替换为你的实际信息）：

我要把 [作品集文件夹的完整路径] 发布到 GitHub 上。
我的 GitHub 用户名是 [用户名]，仓库名是 [仓库名]。
请按「给AI的说明书.md」中的流程执行，使用我提供的访问密钥。
发布前请检查是否存在不适合公开的信息。

完成后它会告知链接地址。

关于访问密钥

密钥不要直接写在对话里，除非你确认该对话不会被他人看到。 更稳妥的做法是让 AI 助手引导你把它设置成环境变量（终端里执行 export GITHUB_TOKEN=...）， 或回答“已设置好环境变量”。

做法二：手动执行

需要用到「终端」，即电脑上可以输入文字的命令行窗口：Mac 系统称为「终端」， Windows 系统称为「命令提示符」。按顺序复制下列内容，每行执行一次。

# 1. 进入这份说明所在的文件夹（路径替换为实际存放位置）
cd "说明文件所在的文件夹路径"

# 2. 提供访问密钥（等号后替换为第三步骤复制的字符）
export GITHUB_TOKEN=此处粘贴复制的字符

# 3. 预演，只列出将要上传的文件，不会真正上传
python3 "配套文件（交给AI用）/脚本/publish.py" \
  --owner 你的用户名 --repo 你的仓库名 \
  --dir "你的作品集文件夹路径" --message "第一次上传" --dry-run

# 4. 确认列表无误后，去掉 --dry-run 再执行一次，即为正式上传
python3 "配套文件（交给AI用）/脚本/publish.py" \
  --owner 你的用户名 --repo 你的仓库名 \
  --dir "你的作品集文件夹路径" --message "第一次上传"

出现 ✅ 已发布 表示上传成功。

路径填写说明

路径中包含空格或中文时，必须使用引号包裹。
Mac 系统如需获取文件夹的完整路径，可将其拖入终端窗口，路径会自动填入。
此步骤只完成文件上传，网页还需要在第五步手动开启。

Windows 系统的差别

上面第二条命令里的 export 是 Mac 与 Linux 的写法。 在 Windows 上：

使用「命令提示符」时，改为：set GITHUB_TOKEN=此处粘贴复制的字符
使用「PowerShell」时，改为：$env:GITHUB_TOKEN="此处粘贴复制的字符"

其余命令两种系统相同。若不确定哪一种，推荐交由 AI 助手完成（做法一），可以避开这些差别。

第七步：发布前内容审查

重要说明

该网址是公开的。任何获得链接的人都可以访问，包括你当前就职机构的同事，以及未来可能面试你的公司。

以下内容不得出现在公开页面上。

不得出现的内容原因处理方式
公司名称、简称、英文名通过搜索即可关联到你当前或曾经的就职机构替换为中性表述
公司的产品名、品牌名、注册商标同上，且涉及法律问题全部替换
真实姓名、电话、邮箱涉及个人隐私删除或进行遮挡处理
内部系统名称、项目代号会暴露内部信息改为通用表述
截图中未遮挡的品牌标识、姓名、手机号程序无法自动识别，只能通过人工检查逐张查看并处理
同事、上级的姓名同上删除
密码、访问密钥会导致账号被盗用任何情况下都不得放入

已发布内容发现问题时的处理

不要直接提交修改

如果内容已经上传，之后才发现其中包含不适合公开的信息， 不要采用「修改后重新上传」的方式。 GitHub 会把你删除的内容完整展示给所有查看提交记录的人，等同于将问题公开。

正确的处理方式是：将原仓库改名并转为私有（相当于封存）， 然后新建一个仓库，重新上传经过处理的内容。这一步可以交由 AI 助手完成，向它说明情况即可。

判断标准

可以用一个简单的标准自检：这份材料，是否愿意让一位完全不认识的陌生人看到？ 如果不愿意，就不适合公开。

第八步：以后修改内容

修改本地文件后，重新执行第四步（两种做法都可以），再等待一到两分钟即可生效。

说明

本地文件夹是内容的正本，网上的站点是展示用的副本。 建议始终在本地修改后再同步，避免本地与线上内容不一致。

上传了，但线上还是旧内容

这是最常遇到的情况，多数时候不是操作出错。按下面顺序逐条排查：

先看这里怎么判断怎么办
是否真的上传成功 上传过程中是否出现「成功」一类的提示 没有提示就重新执行第四步
等待时间是否够 刚上传完就立刻打开网址 网站更新需要一定时间，通常一两分钟，偶尔更久，稍后刷新再看
是否是浏览器记着旧版本 手机上看到的是新内容，电脑上还是旧的（或反之） 在电脑上强制刷新（Ctrl + F5），手机上清理缓存，或换一个浏览器
上传的是否为改动后的文件 改了内容，但上传的还是之前那份文件夹 确认本地文件已保存，再重新上传一次
是否漏传了配套文件 页面能打开，但排版错乱或正文一片空白 检查 .nojekyll 与 assets 是否都在文件夹里
上传是整体替换，不是只增不减

本地删掉的文件，线上也会一并消失；本地没有的文件，线上也不会有。 所以每次上传前，先确认本地文件夹是完整、正确的。

常见问题

打开网址显示 404

通常有两种原因：一是刚发布完成，需要再等待一到两分钟； 二是第五步的发布开关未保存成功，需返回检查。

修改后刷新仍是旧内容

多数是更新延迟或浏览器缓存，按第八步的排查表逐条查看即可，不必改动文件。

页面出现乱码或排版异常

多数情况由文件名中的特殊字符引起。将文件名改为英文字母与数字的组合后重试。

不想让他人看到仓库名称

仓库名称会出现在网址中，因此建议在创建时就使用中性名称。 已经创建的可随时在 Settings 中修改，修改后网址会同步变更。

电脑上没有 Python

Mac 系统通常自带。Windows 系统可在 python.org 下载安装包， 安装过程中需要勾选「Add Python to PATH」。

网址太长，能否缩短

可以绑定自有域名（需另行购买），但这不是必须项，建议先确保流程跑通。

上传 / 发布 / deploy / 部署把本地文件夹的内容放到网络上
分支 / branch / main主线版本，可理解为「当前版本」
静态网站 / 静态托管不需要后台程序的网页，内容由文件直接构成
域名网址
缓存 / CDN网站会保存副本，修改后需要等待一段时间才显示最新内容
渲染把文件内容显示成页面
终端 / 命令行 / shell可以输入文字的命令行窗口
脚本一段自动完成指定任务的程序
JSON一种供程序读取的、格式规整的文本文件
Markdown / .md一种带简单排版的纯文本格式，本文最初即以此格式撰写

完成以上步骤后，一个可长期使用的在线作品集就建立好了。之后新增项目或更新内容， 重复「修改本地文件 → 重新上传 → 等待一分钟」即可。

需要说明的是：技术操作只占整件事的一部分。 内容是否经过充分处理、排版是否清晰，对阅读者的判断影响更大。
